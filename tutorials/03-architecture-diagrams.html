Tutorial 03 · Visualization

Generate architecture diagrams

Use IBM Bob to analyze the Galaxium Travels codebase and generate Mermaid UML class diagrams, sequence diagrams, and use case diagrams. Use context mentions in Ask mode to explore code and Agent mode to save results to your repository.

Overview

What you will learn

Architecture diagrams give you a shared visual language for a codebase before you modify it. In this tutorial, you use Bob to read the Galaxium Travels source files and generate three types of UML diagrams using Mermaid markup:

Diagram typeWhat it shows
UML class diagramData model — entities, attributes, and relationships between them
Sequence diagramRuntime flow — how components interact in a specific lifecycle, ordered by time
Use case diagramActors and capabilities — all actors and the features each actor can exercise
Key features you learn

Context mentions (@) — Reference specific files/folders to give Bob precise analysis scope.
Ask mode — Safely explore code and generate diagram markup without modifying files.
Agent mode — Write the generated diagrams to the repository.
GitHub provides native Mermaid rendering in Markdown files, so you can commit the .md files and view rendered diagrams directly on GitHub.

Prerequisites

What you need

  • Bob IDE installed.
  • Git installed locally.
  • Familiarity with the basics of Bob. If new, start with the Quickstart tutorial.
Note — default branch

This tutorial uses the default branch of Galaxium Travels (not bob-learning-path-branch), which contains the full multi-service codebase needed for accurate diagram generation.

Step 01

Set up your workspace

Clone the repository

bash
git clone https://github.com/Navya-1103/galaxium-travels

Open the project in Bob IDE

  1. Launch IBM Bob IDE and open the galaxium-travels folder.
  2. Open the Bob chat interface (⌥⌘B on Mac / Ctrl+Alt+B on Windows).
  3. Review README.md in the root directory to get an overview of the application architecture.

Initialize project context

Run /init in Agent mode to generate AGENTS.md context files. Review the generated files to understand how Bob has set up the project context.

bob chat
/init

Switch to Ask mode

Select Ask in the mode selector, or type /ask. Ask mode is read-only — Bob can read and analyze files but cannot create or modify anything.

Step 02

Generate a UML class diagram

A UML class diagram maps the data model of an application: the entities (classes), their attributes, and the relationships between them. For Galaxium Travels, this covers the Python SQLAlchemy models in the backend and the Java domain classes in the inventory hold service.

Raw markup tip

By default, Bob outputs Mermaid diagrams as rendered images. To review the raw Mermaid markup, add the instruction "Output only the Mermaid code block. Do not render the Mermaid diagram." to your prompt.

bob prompt — Ask mode
Analyze the data models in @booking_system_backend/models.py and the Java domain classes in @booking_system_inventory_hold_service/src/main/java/com/galaxium/holdservice/domain. Generate a Mermaid classDiagram that shows all classes, their attributes, their methods (if any), and the relationships between them. Include the BookingStatus enum. Output the Mermaid markup. Do not render the Mermaid diagram.

Bob reads both files and produces a classDiagram that covers:

  • Python/SQLAlchemy models: User, Flight, Booking, BookingStatus
  • Java/JPA models: Quote, Hold, AuditEvent, QuoteStatus, HoldStatus
  • All relationships between entities (1-to-many, enumerations)
Step 03

Generate a sequence diagram

A sequence diagram shows how components interact at runtime in a specific flow, ordered by time. The Galaxium Travels booking flow spans the React frontend, the Python FastAPI backend, and the Java inventory hold service.

bob prompt — Ask mode
Analyze the booking flow across @booking_system_frontend/src/services, @booking_system_backend/server.py, @booking_system_backend/services/booking.py, and @booking_system_inventory_hold_service/src/main/java/com/galaxium/holdservice/api. Generate a Mermaid sequenceDiagram showing the complete flow for a user booking a flight, including the quote and hold steps with the Java service. Output the Mermaid markup. Do not render the Mermaid diagram.

Bob traces the interaction chain across all three services and produces a sequenceDiagram that covers:

  • Phase 1 — Create Quote: User → Frontend → Python backend → Java QuoteService → Database
  • Phase 2 — Create Hold: Quote ID → HoldService → 15-minute hold reservation
  • Phase 3 — Confirm Hold → Create Booking: Hold confirmation → Python BookingService → seat decrement → Booking record
  • Error paths: booking failed (name mismatch / no seats / user not found)
Step 04

Generate a use case diagram

A use case diagram identifies the actors in a system and the capabilities each actor can exercise. Mermaid does not have a native use case diagram type, so you represent this with a flowchart LR that groups use cases by actor.

Escaping curly braces

Instruct Bob to escape curly braces in the Mermaid markup so the renderer does not attempt to interpret them as template syntax. Use &#123; for { and &#125; for }.

bob prompt — Ask mode
Analyze the full Galaxium Travels application. Identify all actors (user types or external systems) and the use cases each actor can perform, based on the frontend pages, backend REST endpoints, and MCP tools. Generate a Mermaid flowchart LR that represents this as a use case diagram, grouping use cases under their respective actors using subgraphs. Escape curly braces in Mermaid markup so that the Mermaid renderer does not attempt to interpret the curly braces as template syntax. Output the Mermaid markup. Do not render the Mermaid diagram.

Bob analyzes the application and produces a flowchart with subgraphs for each actor:

  • Traveller (Browser) — browse flights, search/filter, register, sign in, select seat class, quote, hold, confirm, view/cancel bookings
  • AI Agent (MCP Client) — list_flights, register_user, get_user_id, book_flight, get_bookings, cancel_booking
  • Java Hold Service (Internal) — confirm hold via internal endpoint, auto-expire holds
  • Python REST API (External Consumers) — all public REST endpoints
Step 05

Save diagrams to the repository

Switch to Agent mode

Select Agent in the mode selector, or type /agent.

Save all three diagrams

bob prompt — Agent mode
Create a docs/architecture/ folder in the repository root. Save each of the three diagrams we generated as individual Markdown files: - class-diagram.md — the UML class diagram - sequence-diagram.md — the booking flow sequence diagram - use-case-diagram.md — the use case flowchart Each file should have a short title heading, the Mermaid code block we generated, and a brief description of the diagram.

Bob creates the three files. Click Approve and Save for each file Bob writes.

Verify the output

Open each file in the Bob file explorer to confirm the Mermaid fenced code blocks are present. To preview a rendered diagram:

bob prompt
Show me a preview of docs/architecture/class-diagram.md
GitHub rendering

Commit and push the changes to a GitHub repository — GitHub natively renders Mermaid diagrams in Markdown files, so you can view all three diagrams rendered directly on GitHub without any additional tooling.

Troubleshooting

Mermaid markup that does not compile

Mermaid's parser is strict. Use the following reference to diagnose and fix issues. Paste failing markup into the Mermaid Live Editor to see the exact parse error.

SymptomLikely causeFix
Parse error near { or }Curly braces unescaped in labelsReplace with &#123; and &#125;
Parse error near ( or )Parentheses in a node IDWrap the label in quotes: A["label (note)"]
Unexpected end or subgraph errorSubgraph not closedEnsure every subgraph block has a matching end
Arrow type not recognizedWrong arrow syntax for diagram type--> for flowchart; ->> / -->> for sequenceDiagram
Diagram renders partially then stopsLabel contains a bare " characterEscape quotes inside labels

To ask Bob to fix a specific parse error:

bob prompt
The Mermaid classDiagram fails to parse with this error: [paste error here]. Fix the syntax so it compiles without changing the diagram structure.
Business Value

Traditional approach vs. IBM Bob

Architecture diagrams are critical for alignment, onboarding, and change planning — but in most teams they are either missing, outdated, or locked in a slide deck no one can find.

Traditional approach
  • Architect spends 2–4 hours manually tracing the codebase and drawing diagrams in Visio or Lucidchart
  • Diagrams drift from the codebase within weeks and are rarely updated
  • Each diagram type (class, sequence, use case) requires separate manual effort
  • Diagrams live in external tools — not version-controlled alongside the code
Half a day per diagram type, plus ongoing maintenance
With IBM Bob
  • Bob reads the source files and generates all three diagram types in a single session
  • Diagrams are committed as Markdown files — rendered natively on GitHub, always alongside the code
  • Regenerate any diagram after a sprint's changes in under 5 minutes
  • No external tooling, no licenses, no drift
Under 15 minutes for all three diagrams
Time saved: a full day of manual diagramming work per sprint cycle. Diagrams stay current because regenerating them costs almost nothing.
