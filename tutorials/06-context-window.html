Tutorial 06 · Context Management

Create a new context window

Manage Bob's context window to preserve memory, control cost, and maintain output quality during complex or long-running conversations.

Overview

Why context management matters

Every task (conversation) in the chat panel has a context window. The context window is the token limit for what Bob can hold in memory for the current session. Context includes system instructions, tool schemas, your rules and skills, and the full transcript.

Token cost

Tokens are the unit of consumption for Bob, measured in Bob coins. Longer conversations and larger file reads consume more tokens. Keeping conversations focused reduces cost. Every prompt re-sends the full active context — a one-line question still carries Tool definitions, Rules, and whatever else Bob loads by default.

Summarization is lossy

When Bob reaches its token limit, Bob condenses older content to keep working — which drops detail. You can lose edge cases, intermediate reasoning, and constraints you stated many prompts ago. If you still need content details, start a new task before Bob summarizes it away.

Quality degrades before the limit

Bob currently uses a 270.0k token window. Quality often drops before you reach it. As Messages grows, replies get less reliable.

Key Terms

Terminology

TermDefinition
TaskOne conversation thread with its own context window. Start a new context window with + (New task).
Context window breakdownClick the token usage indicator in the top right of the chat panel to see where tokens go.
System promptBob's core instructions for this session.
Tool definitionsSchemas for Bob's built-in tools and connected MCP tools.
RulesCustom instructions from your project and mode (e.g., AGENTS.md).
SkillsInstructions from any skills Bob loaded during the task.
MessagesYour prompts, Bob's replies, and tool activity in the task (counted as tokens).
Prerequisites

What you need

  • IBM Bob IDE v2.x or later.
  • Git to clone the example repository.

Step 01

Set up the lab

  1. Clone the Galaxium Travels repository:
bash
git clone -b bob-learning-path-branch https://github.com/IBM/galaxium-travels
  1. Click File then Open Folder. Navigate to the galaxium-travels directory you cloned and open it.
  2. Open the Bob chat interface by clicking the Bob icon beside the navigation bar, or use the shortcut Option + Command + B (macOS) or Ctrl + Alt + B (Windows).
  3. In the chat input field, run /init. Bob scans the repository and creates an AGENTS.md file with project rules. Click Approve todo tools for task if prompted. Wait for Bob to report that it finished.
Why run /init first?

This AGENTS.md is what later appears as the Rules line in the context window breakdown, so the repository needs it before you measure a baseline.

Step 02

Read the context window breakdown

  1. Click + (New task) at the top of the chat panel to start a fresh task.
  2. Send a minimal prompt to use a small amount of tokens:
bob prompt
Quickly say hi back.
  1. Wait for Bob's reply.
  2. Click the token usage indicator in the top right of the chat panel to see the usage breakdown.

After this exchange on Galaxium Travels, your numbers will vary, but you will see numbers close to:

CategoryTokens
Total used8.5k (~3% full)
System prompt1.5k
Tool definitions5.1k
Rules830
Skills454
Messages590
Reserved for model response20.0k
Available space241.5k
Note

Tool definitions is usually the largest fixed category. MCP servers and built-in tool schemas load whether you call them or not. On Galaxium, fixed categories total roughly 8k before meaningful work — you pay that on every turn, whether you typed it or not.

Step 03

Grow messages with a prompt

Stay in the same task. Send a prompt that fills the transcript:

bob prompt
List all of the files in this directory.

Approve read actions if prompted. Bob lists files in the repository. Now open the breakdown again and compare:

CategoryFresh taskAfter list-files
System prompt1.5k1.5k
Tool definitions5.1k5.1k
Rules830830
Skills454454
Messages590~4.2k
Total used8.5k (~3%)12.1k (~4%)

Messages should now read about 4.2k. The key insight: Messages grew while the fixed categories did not. List output and tool activity sit in the transcript. Over time, Messages is usually what grows fastest.

Step 04

Create a new context window

Start a new task in the same project. The old task (conversation) stays in history.

  1. Click + (New task) at the top of the chat panel.
  2. The indicator resets. Messages drops back to a small number.
  3. System prompt, Tool definitions, Rules, and Skills reload to roughly the baseline.
Note

The task you left stays in the task list, and you can switch back at any time. It keeps its own transcript and token count. Bob does not use it while you work in the new task.

When to start a new task

  • You switch topics or work goals.
  • Messages is large enough to hurt quality or cost. On Galaxium, 19.4k in Messages is a reasonable signal to reset.
  • You finished planning and want a clean task for implementation.

Reflection

Open the breakdown on the new task. Which categories returned to baseline? Which would have kept growing if you had stayed in the old task?
