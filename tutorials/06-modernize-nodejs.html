Tutorial 06 · Modernization

Modernize a Node.js application

Learn to use IBM Bob for application modernization by upgrading a TypeScript Express API from Node.js 16 to 22. Try AI-assisted development with modes, approvals, and literate coding in this hands-on tutorial.

Overview

What you will learn

In this tutorial, you modernize a TypeScript Express REST API from Node.js 16 to Node.js 22. You do not need experience in Node.js or TypeScript. You learn how Bob analyzes dependencies and modernizes code patterns.

Bob provides four essential capabilities you use throughout this upgrade:

Modes Context mentions (@) Approval workflow Literate coding
FeatureWhat it does in this tutorial
ModesSpecialized personas (Ask, Agent) that tailor Bob's behavior for specific tasks
Context mentionsReference specific project files (@package.json, @tsconfig.json, @Dockerfile) in your prompts
Approval workflowReview every tool Bob plans to use before it executes — you stay in control
Literate codingWrite instructions in plain language directly in the editor; Bob generates the code change as a diff
Prerequisites

What you need

  • Docker installed and running on your workstation. You use Bob to create a Dockerfile for the application.
  • IBM Bob IDE installed.
  • You have completed the Quickstart tutorial to familiarize yourself with Bob's interface.
  • You may want to start a new context window for this tutorial.
Different repository

This tutorial uses a different repository from the other labs — the bob-demo repo, not Galaxium Travels. Clone it in the next step.

Step 01

Set up your workspace

Launch IBM Bob and open the Bob sidebar

Launch the IBM Bob application. If the Bob sidebar is not already open, click the Bob icon beside the navigation bar or press ⌥⌘B (Mac) / Ctrl+Alt+B (Windows).

Clone the tutorial repository

Clone the repository by clicking the files icon on the top left of the Bob IDE panel, then click Clone Repository, and paste the following URL:

repository URL
https://github.com/IBM/bob-demo

Bob asks where you want to save the repository. When prompted to open the cloned repository, click Open. If Bob asks "Do you trust the authors?", click Yes, I trust the authors.

Disable auto-approval

Make sure auto-approval is turned off in Permissions. With auto-approval off, Bob asks for your permission before executing any proposed changes.

Step 02

Build the containerized environment

Create a Dockerfile to run the application in a containerized environment, eliminating the need to install Node.js or dependencies locally.

Switch to Agent mode

Switch Bob to Agent mode by clicking the mode dropdown and selecting Agent. Agent mode allows Bob to write, modify, and refactor code — while still asking for permission before each operation.

Create the Dockerfile

bob prompt — Agent mode
Create a Dockerfile for this Node.js TypeScript application. It should use Node 16 to match the current application version, build the TypeScript code, and run the app on port `3000`.

Bob requests read access to several files to understand the requirements. Click Approve. Bob determines the appropriate Dockerfile structure and shows you the proposed file. Click Save to create the file.

Note

You will update this Dockerfile later to use Node 22 once the modernization is complete.

Step 03

Verify the legacy application builds

Before modernizing, verify that the legacy code builds and runs correctly. This baseline ensures you can identify any issues the modernization introduces.

bob prompt — Agent mode
Build and test the legacy application using Docker to verify it works correctly before modernization. The application should respond to API requests at /api/todos with sample data. After testing, clean up the container.
Expected issue: missing package-lock.json

During the build phase, Bob tells you the build failed because the Dockerfile uses npm ci, which requires a package-lock.json file that doesn't exist. Bob detects this and proposes a fix: change npm ci to npm install in the Dockerfile. Approve the fix.

Once Bob applies the fix and finishes the build, it displays a summary confirming the legacy application works correctly. You now have a verified baseline.

Step 04

Explore the Node.js codebase with Ask mode

Switch to Ask mode — it can only read files, so you can safely explore code without accidentally making changes. Use @ context mentions to point Bob at specific files.

Analyze package.json

bob prompt — Ask mode
@package.json What Node.js version is this project using? What dependencies would need updating for Node.js 22? Give me a short summary.

Bob identifies needed updates: @types/node (^16 → ^22), typescript (^4 → ^5). Express and UUID are already compatible with Node 22.

Analyze tsconfig.json

bob prompt — Ask mode
@tsconfig.json What module system and compiler settings is this TypeScript project using? What settings would need updating for Node.js 22? Give me a short summary.

Bob recommends updating target (ES2020 → ES2022+), lib, and considering moduleResolution: "node16" for native ESM support.

Analyze the Dockerfile

bob prompt — Ask mode
@Dockerfile What Node.js version does this Dockerfile use? What would need to change for Node.js 22? Give me a short summary.

Bob identifies that node:16-alpine needs to change to node:22-alpine in both the builder and runtime stages — and that both must be updated in sync to avoid subtle runtime errors.

Step 05

Modernize the API with Agent mode

Switch back to Agent mode. Bob determined the following modernization requirements:

  • Change Node.js 16 to Node.js 22 in package.json and Dockerfile
  • Update the TypeScript compiler target and module settings in tsconfig.json
  • Fix outdated dependency versions
bob prompt — Agent mode
@package.json @tsconfig.json @Dockerfile Modernize this Express API from Node.js 16 to Node.js 22. Keep the API functionality identical - this is a platform upgrade, not a feature change. Give me a short summary.

After Bob finishes, it displays a summary of all changes made:

Changes applied across three files
Dockerfile — 2 lines changed
FROM node:16-alpine AS builder
FROM node:22-alpine AS builder
package.json — 3 fields changed
"node": "16.x" / "@types/node": "^16.18.0" / "typescript": "^4.9.5"
"node": "22.x" / "@types/node": "^22.0.0" / "typescript": "^5.0.0"
tsconfig.json — 4 settings changed
target: ES2020 / lib: ["ES2020"] / module: commonjs / moduleResolution: node
target: ES2023 / lib: ["ES2023"] / module: node16 / moduleResolution: node16
TypeScript 5 gotcha

TypeScript 5 enforces that module and moduleResolution must be set consistently. moduleResolution: "node16" requires module: "node16". The compiled output is still CommonJS-compatible; this only affects how TypeScript resolves imports during type-checking.

Step 06

Mark the modernization complete with literate coding

Use Bob's literate coding feature to update the sample todo title, marking the app as modernized. Literate coding lets you write instructions in plain language directly in your editor instead of using the chat interface.

Enable literate coding mode

  1. In the Explorer tab, navigate to the express-todo-api folder and open src/db.ts.
  2. Toggle literate coding mode by clicking the magic wand icon in the editor toolbar, or press ⌘I (Mac) / Ctrl+I (Windows/Linux).

Write your instruction

In the src/db.ts file, paste the following instruction at the top of the file, before any code:

literate coding instruction — top of src/db.ts
// Find the sample todo object's title property and change it to "Welcome to the Modernized Node.js 22 API"

Bob understands this comment is an instruction (not regular code) because you are in literate coding mode. Your instruction appears highlighted in the editor.

Generate and accept the changes

  1. Click Generate at the bottom of the document. Bob locates the sampleTodo object and shows you the diff.
  2. Review the change: title changes from "Learn Node.js modernization" to "Welcome to the Modernized Node.js 22 API".
  3. Click Accept all to apply the change.
  4. Click Exit under the literate coding wand to exit literate coding mode.
Step 07

Verify the modernized application with Docker

Switch back to Agent mode and verify the modernized application works correctly by rebuilding and testing the Docker container.

bob prompt — Agent mode
Verify the modernized Node.js 22 application works by building and testing it with Docker. Check that the API responds at /api/todos and shows the updated todo title. Clean up when done. Give me a short summary. I also want to see the validation of the new title.

Once Bob verifies the application, it gives you a summary similar to:

Expected verification output

✅ Docker image built successfully with Node.js 22
✅ TypeScript compilation completed without errors
✅ API endpoint /api/todos responds successfully
✅ Updated todo title displays: "Welcome to the Modernized Node.js 22 API"
✅ Cleanup completed (container and image removed)

The API works correctly and the title is updated — confirming that Bob preserved existing behavior while modernizing the Node.js version and all dependencies.

What you accomplished

In this tutorial you used four of Bob's core capabilities together:

  • Agent mode — created the Dockerfile, verified the legacy build, and applied modernization changes.
  • Ask mode — safely analyzed all three config files using @ context mentions before making any changes.
  • Approval workflow — reviewed and approved every file write and command execution step by step.
  • Literate coding — made a targeted in-editor change with a plain-language instruction, reviewed the diff, and accepted.
Business Value

Traditional approach vs. IBM Bob

Upgrading runtime versions is routine maintenance that is routinely deferred — because the research, dependency analysis, and testing effort is disproportionate to the perceived value.

Traditional approach
  • Developer manually reads Node.js migration guides and changelog for breaking changes
  • Dependency compatibility checked one package at a time against release notes
  • TypeScript config changes require research — easy to introduce subtle module resolution bugs
  • Upgrade deferred until forced by end-of-life — making the eventual jump riskier
1–3 days of research and manual testing per major version upgrade
With IBM Bob
  • Ask mode reads package.json, tsconfig.json, and Dockerfile and produces a precise upgrade plan in seconds
  • Agent mode applies all changes across all config files consistently in a single operation
  • Literate coding lets you make in-editor changes with plain-language instructions and review the diff before accepting
  • Docker verification confirms the modernized app works before any commit is made
Under 30 minutes from legacy to verified Node 22
Time saved: up to 3 days of upgrade research and manual testing. Upgrades become routine tasks instead of deferred risks.
