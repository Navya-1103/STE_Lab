Tutorial 04 · Team Standards

Standardize Bob's behavior

Standardize Bob's behavior across your team using project-level rules files that tell Bob to document its code and remember its previous actions.

Overview

What are Bob rules?

Bob rules are plain text files that define instructions applied to every Bob conversation. Bob stores rules as files in a designated folder within the project or at the global user level, and automatically injects the content of every rules file into each conversation across all modes.

Rule injection lets teams and individual developers enforce coding standards, communication preferences, and workflow constraints without repeating instructions in every prompt.

Project-level rules in galaxium-travels/.bob are version-controlled alongside your code, which means:

  • Rules propagate automatically to all team members who clone the repository.
  • Changes to rules go through the normal code review process.
  • The rules history is tracked in git.
Prerequisites

What you need

  • Clone the Galaxium Travels demo code:
bash
git clone -b bob-learning-path-branch https://github.com/IBM/galaxium-travels
  • IBM Bob IDE open with the Galaxium Travels project loaded.
  • Complete Tutorial 01 to create the .bob folder.
  • Python or Python 3. You can download Python from the official website.
Step 01

Create the rules folder

If a rules folder does not already exist in .bob, create one:

bash
mkdir -p galaxium-travels/.bob/rules
Step 02

Create the rules file

Create a file in galaxium-travels/.bob/rules/ called basic_rules.md:

bash
touch galaxium-travels/.bob/rules/basic_rules.md
Step 03

Add custom Bob rules

In the basic_rules.md file, add the following three rules:

Documentation standard rule

This ensures Bob generates consistent documentation whenever it writes or modifies public functions, regardless of the task.

markdown
Always include concise JSDoc strings for every public function.

Communication style rule

Controls how Bob phrases responses and comments — useful for teams that prefer terse, direct output over detailed explanations.

markdown
Be very concise in your wording.

Internal monologue rule

Produces a persistent log of everything Bob has done across all conversations. This gives you an audit trail, cross-session continuity, and team transparency.

markdown
Write a summary of every interaction into the folder `internal-monologue/`. Name the file starting with a timestamp, followed by a concise description of the interaction. Example: 2026-01-15_update-readme.md

Complete basic_rules.md

Once you add all three rules, your basic_rules.md file will look like this:

galaxium-travels/.bob/rules/basic_rules.md
Always include concise JSDoc strings for every public function. Be very concise in your wording. Write a summary of every interaction into the folder `internal-monologue/`. Name the file starting with a timestamp, followed by a concise description of the interaction. Example: 2026-01-15_update-readme.md
Step 04

Test the rules

Open the agentic chat sidebar, switch to Code mode, and run the following prompt to have Bob edit the README.md. Bob may make suggestions such as enhancing troubleshooting, a complete overhaul, or fixing inaccuracies. You can pick the suggestion that best fits your vision.

bob prompt
Update the readme
Expected result

Bob updates the README.md and creates a folder called internal-monologue/ with a file that shows you the updates it made to the README — demonstrating that the rules are being applied.

Next steps
