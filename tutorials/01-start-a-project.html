Tutorial 01 · Getting Started

Start a project with /init and AGENTS.md

Give Bob persistent project context across conversations and modes with /init, which automatically generates AGENTS.md files.

Prerequisites

What you need

To complete this tutorial, you need the following:

  • Clone the Galaxium Travels demo code. The clone command also checks out the bob-learning-path-branch that contains the code you use in the tutorials.
bash
git clone https://github.com/Navya-1103/galaxium-travels
  • IBM Bob IDE open with the Galaxium Travels project loaded.
  • While not required, consider doing the Quickstart tutorial to familiarize yourself with Bob's interface and features.
Step 01

Run /init

The /init command scans a project and generates a structured summary file called AGENTS.md that Bob uses as persistent context in every conversation. It is how you give Bob knowledge about a project's structure, conventions, and codebase without requiring Bob to re-read every file at the start of each interaction.

Why this matters

Large language models are stateless. Each new conversation starts with no memory of previous interactions. Without explicit project context, Bob must discover the codebase on every new interaction — which is inefficient at scale. Running /init solves this.

How to run /init

  1. In Bob IDE, navigate to the Hi, I'm Bob chat interface.
  2. Switch to Agent mode using the mode selector at the bottom of the sidebar.
  3. Enter the /init command in the chat interface.
bob chat
/init
  1. If you have auto-approval disabled, Bob asks your permission to read files and write the AGENTS.md files. Click Approve.
  2. Bob reads the relevant files in the project, then generates the main AGENTS.md file in the Galaxium Travels root directory and a .bob folder with mode-specific AGENTS.md files.
Step 02

Explore AGENTS.md files

The AGENTS.md files function like onboarding documentation for Bob. AGENTS.md is a concise, actionable summary that provides everything Bob needs to understand the project's structure and conventions.

You can locate the main AGENTS.md file at the bottom of the Bob file explorer on the left-hand side. Open the file to read its contents.

The AGENTS.md file typically contains the following components:

  • Project overview and purpose
  • Directory structure and key file locations
  • Technology stack and dependencies
  • Architectural patterns and conventions
  • Development workflows

Bob automatically applies the AGENTS.md to new conversations and learns the project context.

Summary

Next steps

In this tutorial, you learned the following:

  • Large language models are stateless. Running the /init command solves this by generating AGENTS.md — a persistent context file Bob reads at the start of every conversation.
  • The mode-specific AGENTS.md files provide targeted context for Agent, Plan, and Ask modes.
  • Re-run /init after major project changes to keep the context current.
Business Value

Traditional approach vs. IBM Bob

Setting up persistent project context is often treated as optional, but without it every developer and AI interaction restarts from scratch.

Traditional approach
  • Developer manually reads README, directory tree, and key source files to build mental model
  • Context is held in one person's head — lost when they leave the conversation or the team
  • Every new team member repeats the same onboarding from scratch
  • AI prompts must re-explain the project structure every session
2–4 hours per developer, repeated per session
With IBM Bob
  • Run /init once — Bob reads the project and writes AGENTS.md automatically
  • Context is version-controlled, shared with the whole team, and available to Bob instantly
  • New contributors open the repo and Bob already knows the architecture
  • Re-run after major changes to keep context current — takes under a minute
Under 2 minutes, once per project
Time saved: up to 4 hours of manual onboarding per developer, every session. Context is written once, reused forever.
